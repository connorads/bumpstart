## Match the codebase

- Follow the conventions already in the file you're editing - naming, structure,
  error handling, test style - over your own preferences.
- Use the tools and libraries the project already uses. Adding a dependency to do
  something the project can already do is a change worth asking about first.
- Changing an established convention is its own piece of work: say so, and update
  every existing use in the same change rather than leaving two styles behind.
