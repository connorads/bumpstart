## Write down what you learned

- Comments and docs explain *why*; the what and how should be clear from the
  code. Record a constraint or a decision that would otherwise be lost.
- When something surprises you - a wrong assumption, an approach that failed, a
  non-obvious fix - capture it before moving on.
- Write docs and comments as standing fact, in the present tense. "Replaced X"
  and "no longer uses Y" belong in commit messages, not in the file.
